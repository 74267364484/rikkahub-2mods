# 改版二：工作台和本地存储相连

**目标**：原版的工作台是个沙箱——APP 注入给模型的系统提示词写着"工作区是 sandboxed proot rootfs、
路径必须在 Rootfs 内"，所以模型会回答"我看不到你的设备"。改版二把**手机真实存储**接进工作台，
让 AI 工具和内置终端都能直接读写 `/sdcard`。

**产物**：`apk/RikkaHubMod.apk`
- 包名 `me.rerere.rikkahub.mod`，应用名 `RikkaHub Mod`，版本 **2.5.6-mod.19 (207)**
- SHA256 `1a23316b32d78b3734f9c5197410f08291a2ba15a4266f4b0cdfb441ca6c6231`
- 与官方原版 `me.rerere.rikkahub`、以及任何 `me.rerere.rikkahuc` **都不冲突，可共存**
- v1 + v2 + v3 签名，自建 keystore

---

## 一、装完必做

**授予「所有文件访问权限」**，否则 `/sdcard` 里绝大多数目录读不到，工作台会静默回退到 APP 私有目录：

```
设置 → 应用 → RikkaHub Mod → 特殊权限 → 所有文件访问权限 → 允许
```

或 adb：

```bash
adb shell appops set --uid me.rerere.rikkahub.mod MANAGE_EXTERNAL_STORAGE allow
```

APP 启动时会**自己检查并跳一次**系统授权页（同一进程只提示一次）；桌面快捷方式
「手机存储权限」是随时可用的手动入口。

---

## 二、改了什么

### 1) 手机本地存储可读可写
- Manifest 新增 `MANAGE_EXTERNAL_STORAGE`（"所有文件访问权限"）+ `READ_EXTERNAL_STORAGE`
- proot 启动参数新增绑定挂载：
  - `/storage/emulated/0` → rootfs 内 `/sdcard`
  - `/storage` → rootfs 内 `/storage`（含外置 SD 卡）
- rootfs 内自动预建挂载点目录 `/sdcard`、`/storage/emulated/0`
- 内置终端（工作区 → 终端）同样挂载

效果：终端里 `ls /sdcard`、`cp /sdcard/Download/a.txt /workspace/` 直接可用；
AI 工具 `workspace_read_file` / `workspace_write_file` / `workspace_edit_file` / `workspace_shell`
都能用 `/sdcard/...`、`/storage/emulated/0/...` 绝对路径读写手机文件。

### 2) 提示词和工具描述改了
原来 APP 告诉模型"工作区是 sandboxed proot rootfs、路径必须在 Rootfs 内"，
所以模型会回答"我看不到你的设备"。现在系统提示词 + 4 个工具描述（read / write / edit / shell）
+ `path` 参数说明都改成明确告知：

> `/sdcard` (= `/storage/emulated/0`) 和 `/storage` 是**手机真实存储**
> （相册 / Download / Documents / Pictures / Music / Android/media…），可以直接读写，
> 隐藏文件也可见，不许再说看不到设备文件。

### 3) 工作台文件区默认落在手机存储
`/storage/emulated/0/RikkaHub/workspaces/<工作区ID>/`

- APP 的「文件」页看到的就是手机上真实目录（隐藏文件也列）
- AI 的 `/workspace` 也是这个真实目录

### 4) 换目录的两种方式

**推荐：桌面快捷方式。** 长按桌面「RikkaHub Mod」图标 →
- 「手机存储权限」→ 直接打开系统「所有文件访问权限」页
- 「设置工作台目录」→ 系统目录选择器（SAF）→ 选完自动写入配置并 Toast 提示

**手工：** 建文件 `/storage/emulated/0/RikkaHub/workspace_base.txt`，内容写**一个绝对路径**：

| 内容 | 效果 |
|---|---|
| `/storage/emulated/0` | 整个内部存储当工作台（文件页可浏览全机存储） |
| `/storage/emulated/0/Download` | 就用下载目录 |
| `/storage/emulated/0/my/{root}` | 每个工作区一个子目录（`{root}` 替换成工作区 ID） |

**即时生效**，不用重启 APP（每次读写都会重新读这个文件）。
不建这个文件 → 用默认值 `/storage/emulated/0/RikkaHub/workspaces`。

> 配置只影响「文件区 / `/workspace`」。rootfs（Linux 系统本身）仍在 APP 私有目录里——
> 必须如此：`/sdcard` 是 `noexec`，放那里跑不了程序。

### 5) 写 `/sdcard`、`/storage` 免审批
已加入可写白名单（`WRITABLE_ROOT_PREFIXES = ["/workspace", "/tmp", "/skills", "/sdcard", "/storage"]`）。

### 6) 隐藏文件
核对了 APK 里所有列目录的代码：**只过滤 proot 的 `.l2s.` 临时文件，点开头的隐藏文件本来就显示**
（工作区文件浏览器、rootfs 浏览器、SAF 文档提供器、shell 都一样）。
唯一会"隐藏"点文件的是编辑器自动补全（`WorkspaceIgnoreMatcher` 忽略 `.git`、`node_modules` 等），
那是补全列表，不是文件列表。

### 7) 附带
- 应用名改成 **RikkaHub Mod**，避免和原 APP 图标重名
- 其余功能（聊天、供应商、MCP、技能、WebUI…）一行未动

## 四、踩过并已修掉的坑（详见 `开发记录/改版二/交付记录.md`）

| 问题 | 原因 | 修法 |
|---|---|---|
| 装不上，报"签名冲突" | 二进制 Manifest 里每个属性有 `rawValue` 和 `typedValue` 两个字段，改包名时只改了后者，而 PackageManager 读的是 `rawValue` | 同步改 `rawValue`（provider authority、自定义权限一起改），并用独立第三方解析器交叉验证 |
| 装上闪退 `VerifyError` | 往已有方法里内联插代码时覆盖了别处在用的寄存器（v7 在别处是 boolean） | 全部改成"新增独立辅助方法 + 原方法只加一句调用"，不碰被改方法的寄存器 |
| 手写 smali 参数被覆盖导致崩溃 | `rikkaReportGrantResult` 用了 `.registers 4`，参数 `p0` 落在 `v2`，方法体里又把 `v2` 当普通寄存器用 | 写了 `check_regs.py` 扫描"vN 是否覆盖参数寄存器(pN)" |
| `NoSuchMethodError` | 删方法时漏删调用点（`handleIntent` 仍 invoke 已删除的 `rikkaHandleWorkspaceDirIntent`） | 写了 `check_refs.py` 检查 invoke/iget/iput/sget/sput 引用的本类成员是否存在 |
| `resources.arsc` 资源包名没跟着改 | Firebase/Crashlytics 用 `getIdentifier(名字, 类型, context.packageName)` 查自己资源 | 就地改写 arsc 里的资源包名字段（长度不变） |
| 模型说"看不到你的设备" | 注入的系统提示词写着 sandboxed / 路径必须在 Rootfs 内 | 改提示词 + 4 个工具描述 |
| 没权限时静默降级 | 缺少"检查 + 申请"流程 | 启动时检查并跳授权页 |

## 五、两条技术路线

改版二做过两遍，两条路线的脚本都留档了：

### 路线 A：免源码（smali 直接改）→ `开发记录/改版二/smali补丁/`

```
baksmali 反汇编 → patch_smali.py 打 6 处补丁 → smali 回汇编 → patch_axml.py 改二进制 Manifest
→ patch_arsc.py 改资源包名 → build_apk.py 重建 APK → Sign.java 做 v1+v2+v3 签名
```

| 文件 | 作用 |
|---|---|
| `patch_smali.py` | 对反汇编出来的 smali 打补丁（精确字符串匹配，匹配不到会报错退出） |
| `patch_axml.py` | 给二进制 `AndroidManifest.xml` 追加权限、改应用名/包名（自写 AXML 读写） |
| `axml2.py` | AXML 解析器（校验用） |
| `patch_arsc.py` | 改写 `resources.arsc` 里的资源包名（就地覆盖，长度不变） |
| `build_apk.py` | 用新 dex/manifest 重建 APK（保持条目顺序/压缩方式，未压缩条目 4 字节对齐） |
| `Sign.java` | 用 apksig 做 v1+v2+v3 签名 |
| `replace-*.json` | 各版本（共存版 / 官方包名版 / 诊断版）的替换文件清单 |
| `rebuild.sh` | 一键串起全流程 |

### 路线 B：源码编译（最终产物走的这条）→ `开发记录/改版二/源码改动/`

RikkaHub 2.5.6 源码 + Android SDK 37 + Gradle 9.6，改动全部脚本化：

| 文件 | 作用 |
|---|---|
| `apply_code_changes.py` | WorkspaceManager 外部目录 / `{root}` 占位符 / 配置文件读写 |
| `apply_code_changes2.py` | 工具描述 + 提示词改写、RouteActivity 权限检查与跳转 |
| `apply_code_changes2b.py` | 同上（拆分重跑用） |
| `apply_code_changes3.py` | WorkspaceDetailPage：权限卡片 + 目录选择器 |
| `patch_prompt_and_files.py` | 提示词与文件区默认路径的最终版改动 |
| `fix_smali_verify.py` / `fix_smali_verify2.py` | 修 `VerifyError`（寄存器冲突）用的辅助脚本 |

> 每个脚本都是"精确匹配 + 断言命中次数"的写法，匹配不到会直接报错退出，方便定位。

## 六、已知没做的

- 界面结构基本没动（改 Compose UI 需要源码编译，代价高）
- 「设置工作台目录」走的是**桌面快捷方式 + SAF 选择器**，不是 APP 内嵌页面（功能等价）
- 其他 APP 的 `Android/data`、`Android/obb` 目录读不到——Android 11+ 的系统限制，与本改动无关

---

## 七、⚠️ 安全

**这个版本让 AI 和终端能对整个手机存储读写，误删风险自负。**

- 没有回收站，模型一条 `rm -rf` 就是真没了
- 建议把工作台目录限定到一个**专用子目录**，而不是把整个 `/storage/emulated/0` 交给它
- 别让含密钥、证件照、银行截图、`.ssh`、`auths/*.json` 的目录落在模型视野里
- 重要数据先备份
