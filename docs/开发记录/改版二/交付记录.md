## 二、这个版本已经做了什么

1. **手机存储可读写**：proot 里把 `/storage/emulated/0` 挂到 `/sdcard`，`/storage` 挂到 `/storage`（AI 工具 + 内置终端都能用）
2. **提示词已改**：明确告诉模型 `/sdcard`、`/storage` 是手机真实存储（相册/下载/文档…），可以直接读写、隐藏文件可见，不许再说"我看不到你的设备"
3. **启动检查权限**：APP 启动时检查「所有文件访问权限」，没有就 Toast 提示 + 直接跳系统授权页（每次启动一次，授权后不再打扰）
4. **工作台目录可配置**：默认 `/storage/emulated/0/RikkaHub/workspaces/<工作区ID>`（真实手机目录），可用
   `/storage/emulated/0/RikkaHub/workspace_base.txt` 改成任意目录（支持 `{root}` 占位符），即时生效
5. **写 `/sdcard`、`/storage` 免审批**；隐藏文件本来就显示（只过滤 proot 的 `.l2s.` 临时文件）
6. 应用名改成 `RikkaHub Mod`，包名独立 → 与你已装的原版、二次打包版**共存**，谁都不用动

## 三、踩过并已修掉的坑（记录备查）

| 问题 | 原因 | 修法 |
|---|---|---|
| 装不上，报"签名冲突" | 二进制 Manifest 里属性有 `rawValue` 和 `typedValue` 两个字段，改包名时只改了后者，系统读 rawValue 仍是旧包名 | 同步改 rawValue（provider authority、自定义权限一起改） |
| 装上闪退 VerifyError | 往已有方法里内联插代码时覆盖了别处在用的寄存器（v7 在别处是 boolean） | 全部改成"新增独立辅助方法 + 原方法只加一句调用"，不碰被改方法的寄存器 |
| resources.arsc 资源包名没跟着改 | Firebase/Crashlytics 用 `getIdentifier(名字,类型,context.packageName)` 查自己资源 | 就地改写 arsc 里的资源包名字段 |
| 模型说"看不到你的设备" | APP 注入的系统提示词写着 sandboxed / 路径必须在 Rootfs 内 | 改提示词 + 4 个工具描述 |
| 没权限时静默降级 | 缺少"检查+申请"流程 | 启动时检查并跳授权页 |

## 五、权限申请流程（含排查）

Android 的「所有文件访问权限」(MANAGE_EXTERNAL_STORAGE) 是**特殊权限，没有弹窗式申请**，
只能跳到系统设置页让用户开开关。当前实现：
- APP 启动时（RouteActivity.onCreate）检查 `Environment.isExternalStorageManager()`，
  未授权 → 直接跳设置页；两级回退：APP 专属页 → 所有文件访问列表页 → 最后 Toast 文字指引
- 桌面快捷方式「手机存储权限」= 手动入口，任何时候都能打开该设置页
- 同一进程内只自动跳一次（避免从设置页返回又被弹走）

> 如果"没看到申请"：先确认 设置→应用→RikkaHub Mod→特殊权限→所有文件访问权限 是不是**已经开着**
> （已授权就不该再问）；若确实没开又没跳转，说明该 ROM 没有这个设置页，用快捷方式手动进。

## 七、崩溃排查（不用 adb）

RikkaHub 自带崩溃捕获（`CrashHandler`）：崩溃后**再打开一次 APP**会进「安全模式」界面，
里面显示完整堆栈并能**一键复制**。拿到堆栈直接发我即可定位。

已加固（防再崩）：
- `onResume` 的 `super` 调用改成 `Activity`（原先误引用 `ComponentActivity`，该类中无 `onResume`）
- 所有新增代码路径包 try/catch，异常直接吞掉，不再影响主流程
- 去掉 onCreate 里的重复调用，权限对话框只在 onResume 弹一次

## 八、寄存器冲突（本轮修掉的根因）

手写 smali 时 `rikkaReportGrantResult` 用了 `.registers 4`，参数 `p0` 落在 `v2`，
而方法体里又把 `v2` 当普通寄存器用 → 参数被覆盖 → 崩溃。

已写 `patch/check_regs.py`：扫描 smali，检查"vN 是否覆盖了参数寄存器(pN)"。
修复后 RouteActivity 全量检查 0 冲突。

## 九、"闪退后打不开软件"

APP 内含 CrashHandler：崩溃会写 `crash_handler/crashed=true`，下次启动直接进 SafeModeActivity
（看起来像"打不开")。解决方法：进安全模式页点"清除/继续"清掉该标记，或清除 APP 数据。
