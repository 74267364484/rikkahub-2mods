### ⚠️ 一个已修掉的坑（第一版装不上的真正原因）

二进制 AndroidManifest 里，每个属性有**两个**值字段：`rawValue`（字符串池引用）和 `typedValue`。
我第一版只改了 `typedValue`，**`rawValue` 还留着旧包名** —— 而 PackageManager 读的是 rawValue，所以系统看到的仍是 `me.rerere.rikkahub`，于是报"已安装了签名冲突的应用"。
现已同步修改 rawValue，并用**独立第三方解析器（pyaxmlparser）**交叉验证：两个解析器结果一致，且全清单 0 处 raw/typed 不一致。

## 一、三个"RikkaHub"的关系（很重要）

| | 包名 | 说明 |
|---|---|---|
| 你已装的原版 | `me.rerere.rikkahub` | 不动 |
| 当前跑这个工作台的 APP | `me.rerere.rikkahuc` | 二次打包版（证据：进程路径 `/data/app/~~…==/me.rerere.rikkahuc-…==/lib/arm64/libproot_exec.so`），不动 |
| **本次的魔改版（共存版）** | `me.rerere.rikkahub.mod` | 第三个 APP，应用名 `RikkaHub Mod`，与上面两个互不影响 |

共存版改包名时同步处理了：`package` 属性、7 个 provider authority（fileprovider / documents / androidx-startup / mlkitinitprovider / firebaseinitprovider / floatingx.app.init / jlatexmathinitprovider）、自定义权限 `…DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`，以及 dex 里唯一一处写死的 FileProvider authority（`ShortcutHandlerActivity` 相机快捷方式用）；另外把 `resources.arsc` 里的**资源包名**也一起改成新包名（否则 Firebase/Crashlytics 用 `getIdentifier(名字, 类型, context.packageName)` 查自己的资源会查不到）。
**没有**改：任何类名、`me.rerere.rikkahub.action.*` 广播 action（保持与 manifest 一致）。

> 补充说明：**不改任何 APP 就让"当前这个工作台"看到 `/sdcard` 是做不到的**——我实测过 proot 的逃逸路径（`/proc/<pid>/root`）被 chroot 挡住，rootfs 里也没有 `/storage` 的绑定挂载，且二次打包版 APP 没有"所有文件访问权限"。所以只能靠"换一个装了改动的 APP"这条路。

## 二、改了什么（逐条对应你的需求）

### 1) 手机本地存储可读可写
- Manifest 新增 `MANAGE_EXTERNAL_STORAGE`（"所有文件访问权限"）+ `READ_EXTERNAL_STORAGE`
- proot 启动参数新增绑定挂载：
  - `/storage/emulated/0` → rootfs 内 `/sdcard`
  - `/storage` → rootfs 内 `/storage`（含外置 SD 卡）
- rootfs 内自动创建挂载点目录 `/sdcard`、`/storage/emulated/0`
- 内置终端（工作区 → 终端）同样挂载

效果：终端里 `ls /sdcard`、`cp /sdcard/Download/a.txt /workspace/` 直接可用；
AI 工具 `workspace_read_file` / `workspace_write_file` / `workspace_edit_file` / `workspace_shell` 都能用 `/sdcard/...`、`/storage/emulated/0/...` 绝对路径读写手机文件。

### 2) 读写范围不再局限于工作台目录
- 除工作区文件区外，整个手机存储都可读写（见上）
- 写入 `/sdcard`、`/storage` 不再触发审批弹窗（已加入可写白名单）
- 读任意 rootfs 内路径本来就允许（原有行为）

### 3) 工作台目录可以选在手机存储的哪个文件夹
新增配置：`/storage/emulated/0/RikkaHub/workspace_base.txt`（UTF-8 文本，内容是**一个绝对路径**）

- 内容写 `/storage/emulated/0/RikkaHub/workspaces/{root}` → 每个工作区在手机存储里各有一个子目录（**推荐**，`{root}` 会被替换成工作区 ID）
- 内容写 `/storage/emulated/0/Download` → 所有工作区的 `/workspace` 直接就是这个目录（目录里有啥就是啥）
- **不建这个文件** → 保持原样（工作区文件仍放在 APP 私有目录）

生效方式：**即时生效**，不用重启 APP（每次读写都会重新读这个文件）。
配置只影响"文件区/`/workspace`"，rootfs（Linux 系统本身）仍在 APP 私有目录里（必须如此：`/sdcard` 是 noexec，放那里跑不了程序）。

### 4) 隐藏文件
我核对了 APK 里所有列目录的代码：**只过滤 proot 的 `.l2s.` 临时文件，点开头的隐藏文件本来就显示**（工作区文件浏览器、rootfs 浏览器、SAF 文档提供器、shell 都一样）。
唯一会"隐藏"点文件的是编辑器自动补全（`WorkspaceIgnoreMatcher` 忽略 `.git`、`node_modules` 等），那是补全列表，不是文件列表。
→ 如果你在某处确实看不到隐藏文件，告诉我具体位置（哪个界面/哪一步），我再针对那处改。

### 5) 附带
- 应用名改成 **RikkaHub Mod**，避免和原 APP 图标重名
- 其余功能（聊天、供应商、MCP、技能、WebUI…）一行未动

## 三、安装与授权

1. 安装 `RikkaHub_2.5.6-mod-共存版.apk`（与你已装的原版、二次打包版共存，三个 APP 各用各的数据）
2. 授权"所有文件访问权限"（**必须**，否则 `/sdcard` 里绝大多数目录读不到）：
   - 手机设置 → 应用 → **RikkaHub Mod** → 权限/特殊权限 → **所有文件访问权限** → 允许
   - 或 adb：`adb shell appops set --uid me.rerere.rikkahub.mod MANAGE_EXTERNAL_STORAGE allow`
3. 打开 APP → 工作区 → 新建工作区 → 安装 Rootfs（默认从 `https://cdimage.ubuntu.com/ubuntu-base/releases/24.04/release/ubuntu-base-24.04.3-base-arm64.tar.gz` 下载，可改 URL）
4. 想在手机存储里放工作台文件，就按第 2.3 条建那个配置文件

迁移老数据（可选）：
- 原版/二次打包版里：设置 → 备份（含设置/聊天记录）导出 zip；到 RikkaHub Mod 里恢复该备份（同版本 2.5.6，数据库结构一致）
- 老 APP：工作区 → 文件 → 多选 → 导出，把文件导到手机存储；新 APP 里再把它们放进你指定的工作台目录

## 四、限制与注意

- **其他 APP 的 `Android/data`、`Android/obb` 目录**：即使有"所有文件访问权限"，Android 11+ 也不允许第三方 APP 读，这与本次改动无关
- 卸载重装本魔改版会丢 APP 数据（聊天/工作区），重装后 rootfs 要重新下载
- 现在 AI 和终端能对整个手机存储写入，**误删风险自负**，重要数据先备份
- 本魔改版用自建签名（keystore 已附上）。以后升级本魔改版请用**同一个 keystore** 签名，否则要先卸载
- 只改了这一个 APK。若你想让**正在用的 `me.rerere.rikkahuc`** 那个包也变成这样（真·覆盖升级），把那个 APK 提取出来（MT管理器/APK提取器）给我，我用同一套脚本再打一次；不过它的签名不是我这边能复现的，仍需卸载重装或 root 下用核心破解覆盖

## 五、复现 / 二次开发

`patch/` 目录（全部脚本）：

| 文件 | 作用 |
|---|---|
| `patch_smali.py` | 对反汇编出来的 smali 打 6 处补丁（精确字符串匹配，匹配不到会报错退出） |
| `patch_axml.py` | 给二进制 AndroidManifest.xml 追加权限、改应用名（自己写的 AXML 读写） |
| `build_apk.py` | 用新 dex/manifest 重建 APK（保持条目顺序/压缩方式，未压缩条目 4 字节对齐） |
| `Sign.java` | 用 apksig 做 v1+v2+v3 签名 |
| `patch_arsc.py` | 改写 resources.arsc 里的资源包名（就地覆盖，长度不变） |
| `replace-coexist.json` / `replace-official.json` | 两个版本各自的替换文件清单 |
| `axml2.py` | AXML 解析器（校验用） |

流程（在能跑 JDK 的环境里）：
```bash
# 1) 反汇编（baksmali 2.5.2 / dexlib2，Maven Central 可下）
java -cp baksmali.jar:dexlib2.jar:util.jar:guava.jar:jcommander.jar:antlr.jar \
     org.jf.baksmali.Main d classes.dex -o smali1     # 三个 dex 分别来一遍
# 2) 打补丁
python3 patch_smali.py
# 3) 汇编回 dex（-a 26 => dex 版本 038，与原包一致）
java -cp smali.jar:… org.jf.smali.Main a smali1 -o out1.dex -a 26
# 4) 改 manifest
python3 patch_axml.py 原包.apk AndroidManifest_new.xml --label "RikkaHub Mod"
# 5) 打包 + 签名
python3 build_apk.py
java -cp apksig.jar:. Sign rikkahub-mod.keystore <你的keystore密码> rikkahub <未签名>.apk <输出>.apk
```
> 脚本是针对 2.5.6 的 smali 精确匹配写的，换版本需要重新定位（报错会告诉你哪一处没匹配上）。
