# 改版一：模型调用工具时不需要用户许可

**目标**：原版 RikkaHub 每调用一次工具（shell / 读写文件 / 联网…）就弹一次「允许 / 拒绝」，
一次多步任务要点几十下。让工具调用不再等待人工确认。

**产物**：`apk/RikkaHub_2.5.6-fullaccess_clone.apk`
- 包名 `me.rerere.rikkahuc`，版本 2.5.6 (191)
- 基线：RikkaHub 2.5.6 官方包（`me.rerere.rikkahub`，同样 191）

---

## 一、定位过程

1. 解出两个包的 `classes.dex` / `classes2.dex` / `classes3.dex`，逐字节比对：

   | dex | 结果 |
   |---|---|
   | `classes.dex` | 完全一致 |
   | `classes2.dex` | 完全一致 |
   | `classes3.dex` | **有差异** |

2. 先做字符串表比对（正则扫 dex 里所有 ≥6 字节的可打印串）：**新增 0 条、删除 0 条**。
   → 说明改动不是"加了段代码/加了句提示词"，而是**纯字节码层面的指令替换**。

3. 用 baksmali 把两个 `classes3.dex` 反汇编后 `diff -rq`，**只有 1 个文件不同**：

   ```
   me/rerere/rikkahub/data/ai/GenerationLoop$generateText$1.smali
   ```

### 为什么这样改就生效

原版逻辑（Kotlin 大意）：

```kotlin
if (tool.needsApproval(input) == true && toolMessage.approvalState is ToolApprovalState.Auto) {
    // 标记为"待审批"，挂起等待用户点允许
    booleanRef.element = true
    approvalState = ToolApprovalState.Pending
    ...
}
```

- `v7 = 1`，`if-ne v1, v7, :cond_45c` 的意思是「**v1 ≠ true 就跳到 `:cond_45c`**」。
- 把 `v1` 恒定成 `0`（false），这个分支**必然跳转**，直接跳过上面整段
  "置为 `ToolApprovalState$Pending`" 的代码 → 工具不会被挂起等审批 → 模型调完就执行。
- 跳转目标 `:cond_45c` 落在 2815 行，正好是那段 Pending 代码**之后**的正常流程
  （检查已有审批状态、收尾），所以后续逻辑不受影响。

### 合法性 / 安全性

| 检查项 | 结论 |
|---|---|
| 指令长度 | `move-result v1`（format 11x）和 `const/4 v1, #0`（format 11n）**都是 2 字节**，dex 的指令流偏移、`code_item` 大小、try/catch 表**全都不变** |
| `invoke` 后不接 `move-result` | **合法**。`move-result` 只有在需要返回值时才必须紧跟；不写就是把返回值丢弃，Dalvik/ART 都接受 |
| 寄存器/类型校验 | 只写 `v1`，且 `v1` 原本就是布尔暂存，无类型冲突 |
| 是否动了别处 | baksmali 全量比对：`classes3.dex` 里**仅此一个文件**有差异，`classes.dex` / `classes2.dex` 逐字节相同 |
| 回汇编验证 | 改后 smali 用 smali.jar 重新汇编，**无报错**，可生成合法 dex |

## 三、复现步骤

```bash
# 1) 取官方 2.5.6 的 dex
unzip -o RikkaHub_2.5.6.apk "classes*.dex" -d a/
unzip -o RikkaHub_2.5.6-fullaccess_clone.apk "classes*.dex" -d b/

# 2) 找出差异类（工具见 docs/开发记录/改版二/smali补丁/，baksmali 2.5.2）
CP="baksmali.jar:dexlib2.jar:util.jar:guava.jar:jcommander.jar:antlr.jar:kotlin-stdlib.jar:annotations.jar"
java -cp "$CP" org.jf.baksmali.Main d a/classes3.dex -o sm_a
java -cp "$CP" org.jf.baksmali.Main d b/classes3.dex -o sm_b
diff -rq sm_a sm_b
#   → me/rerere/rikkahub/data/ai/GenerationLoop$generateText$1.smali

# 3) 打补丁：在该方法里把 needsApproval 的 move-result 换成 const/4 v1, 0x0

# 4) 回汇编 + 重打包 + 签名
java -cp "smali.jar:..." org.jf.smali.Main a sm_b -o classes3.dex -a 26
#   然后把 classes3.dex 替换回 APK，重新签名（本包用的是 AOSP 公开测试密钥）
```

> 补丁点是**精确字符串匹配**，换 RikkaHub 版本需要重新定位
> （找 `getNeedsApproval()` 后跟 `booleanValue()Z` + `move-result` + `const/4 v7, 0x1` + `if-ne` 的那一处）。

## 四、风险

- **取消了工具调用的最后一道人工闸门。** 模型想删文件、想发消息、想联网提交东西，不会再问你。
- 本包用的是 **AOSP 公开测试密钥**（`CN=Android, O=Android`，AOSP 源码自带，人人可签），
  因此**任何人都能签一个同包名 `me.rerere.rikkahuc` 的 APK 冒充它**。认准本仓库的 SHA256，
  或者自己用私钥重新签一份。
- 建议**不要**和「改版二（工作台接本地存储）」同时装——那等于「全权限 + 全自动」。
  真要用，先把工作台目录限定到一个专用子目录，别把整个 `/sdcard` 交出去。
